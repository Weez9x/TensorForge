# TensorForge

TensorForge — проект на C++20 для изучения умножения матриц и оптимизации вычислений на CPU.

Цель проекта — пройти путь от простой реализации до оптимизированных алгоритмов, проверяя правильность результатов тестами и измеряя производительность.

## Требования

- Компилятор с поддержкой C++20.
- CMake версии 3.20 или новее.
- Средство сборки, например Make или Ninja.

Команды ниже предназначены для Linux и выполняются из корня проекта.

## Структура проекта

```text
TensorForge/
├── CMakeLists.txt
├── include/
│   └── Matrix.h
├── src/
│   ├── Matrix.cpp
│   └── main.cpp
├── tests/
│   └── MatrixTests.cpp
└── benchmarks/
    └── MatMulBenchmark.cpp
```

## Сборка и запуск примера

```bash
cmake -S . -B build/debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug
./build/debug/tensorforge
```

Программа демонстрирует заполнение, вывод и умножение матриц.

Настройка `.clangd` использует базу команд компиляции из `build/debug`, создаваемую CMake.

## Запуск тестов

После сборки:

```bash
ctest --test-dir build/debug --output-on-failure
```

Проверяются:

- Размеры и значения результата для известного примера.
- Исключение `std::invalid_argument` при несовместимых размерах.
- Сохранение матрицы при умножении справа на единичную матрицу.

## Измерение производительности

Для замеров используется сборка Release:

```bash
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release
ctest --test-dir build-release --output-on-failure
./build-release/matmul_benchmark
```

Benchmark умножает квадратные матрицы размеров `128`, `256`, `512` и `1024`. Обе входные матрицы заполнены единицами.

Для каждого размера выполняются:

1. Один прогревочный вызов без измерения времени.
2. Пять измеряемых вызовов.
3. Вывод времени каждой попытки и среднего времени в миллисекундах.

Время измеряется с помощью `std::chrono::steady_clock`. В замер входит вызов `MatMultipli`, включая выделение и обнуление памяти результата. Заполнение входных матриц и вывод в консоль находятся вне замера.

Для матриц размера `N×N`, заполненных единицами, каждый элемент произведения равен `N`. Benchmark выводит элемент `(0, 0)` как простую контрольную проверку; полноценные проверки выполняются отдельно в тестах.

Результаты зависят от оборудования, компилятора, параметров сборки и нагрузки системы. Размер `1024×1024` в базовой реализации может потребовать заметного времени.

Результаты: IJK и IKJ

Я сравнил два порядка циклов умножения матриц:

IJK — исходная реализация: i → j → k.

IKJ — реализация с переставленными внутренними циклами: i → k → j.

Матрицы хранятся построчно. В IKJ внутренний цикл проходит по соседним элементам строк матрицы B и результата. Такой последовательный доступ может лучше использовать кеш процессора.

Условия измерения

OS: Arch Linux x86_64

Kernel: Linux 7.2.9-arch1-1

Процессор: AMD Ryzen 7 3700U (8) @ 4.00 GHz

Оперативная память: 12GB

Компилятор: GCC 16.2.1

Сборка: CMake Release

Размеры квадратных матриц: 128×128, 256×256, 512×512 и 1024×1024

Для каждого алгоритма и размера: один прогревочный вызов и пять измеряемых запусков

Входные матрицы заполнены единицами

Измеряется вызов функции умножения, включая создание и заполнение нулями матрицы результата

Размер матриц     IJK          IKJ     Ускорение IKJ

128×128        1,977 мс      0,330 мс           6,0×

256×256       14,780 мс      2,925 мс           5,1×

512×512      310,838 мс     19,148 мс          16,2×

1024×1024   7572,490 мс    249,528 мс          30,3×

Ускорение рассчитано как время IJK / время IKJ. Например, 6,0× означает, что IKJ в этом замере выполнил умножение примерно в шесть раз быстрее.

На этой машине IKJ оказался быстрее на всех проверенных размерах. Результаты зависят от процессора, компилятора, настроек сборки и нагрузки системы; они описывают конкретный запуск и не гарантируют такое же ускорение на другом компьютере.
